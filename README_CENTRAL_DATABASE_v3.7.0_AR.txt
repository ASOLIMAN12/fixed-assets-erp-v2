Assets Pro v3.7.0 — قاعدة المستخدمين المركزية
================================================

ما تم تنفيذه
-------------
1) نقل المستخدمين وكلمات المرور والصلاحيات إلى PostgreSQL بدل متصفح كل جهاز.
2) شاشة تهيئة الأدمن تظهر مرة واحدة فقط عندما تكون قاعدة البيانات فارغة.
3) جميع الأجهزة تستخدم نفس حسابات الدخول ونفس الصلاحيات.
4) كلمات المرور محفوظة ببصمة scrypt مع Salt ولا تعاد إلى المتصفح.
5) جلسات الدخول محفوظة مركزيًا، وCookie الجلسة HttpOnly وSameSite وSecure على Render.
6) إنشاء وتعديل وحذف المستخدمين يتم من الخادم بواسطة الأدمن فقط.
7) تعديل حساب أدمن أو ترقية مستخدم إلى أدمن يتطلب رمز بريد من الخادم ويستخدم مرة واحدة.
8) استعادة كلمة المرور تتم برمز بريد يصدره ويتحقق منه الخادم.
9) منع حذف الأدمن ومنع إيقاف أو تخفيض صلاحية آخر أدمن نشط.
10) النسخة الاحتياطية المحلية لا تتضمن المستخدمين أو بصمات كلمات المرور.

متغيرات Render المطلوبة
-----------------------
DATABASE_URL         رابط PostgreSQL الداخلي من Render
INITIAL_SETUP_KEY    مفتاح سري تختاره (12 حرفًا أو أكثر) لحماية إنشاء أول أدمن
RESEND_API_KEY       مفتاح Resend السري
RECOVERY_FROM_EMAIL  onboarding@resend.dev للتجربة

خطوات الترحيل الأولى
--------------------
1) أنشئ PostgreSQL في Render واربط Internal Database URL بالمتغير DATABASE_URL.
2) أضف INITIAL_SETUP_KEY بقيمة سرية لا تقل عن 12 حرفًا ولا تشاركها مع المستخدمين.
3) ارفع ملفات v3.7.0 إلى GitHub وانتظر اكتمال النشر.
4) افتح البرنامج من الجهاز الأساسي.
5) ستظهر تهيئة المستخدم الرئيسي مرة واحدة لأن قاعدة البيانات الجديدة فارغة.
6) أدخل بيانات الأدمن الحالية وكلمة المرور ورمز الاستعادة وقيمة INITIAL_SETUP_KEY.
7) إذا كانت حسابات المستخدمين موجودة على الجهاز الأساسي فسيتم نقلها تلقائيًا مع صلاحياتها.
   تتحول بصمة كلمة مرور كل مستخدم إلى scrypt تلقائيًا عند أول دخول له.
8) افتح البرنامج من جهاز آخر؛ ستظهر شاشة الدخول فقط ولن تظهر شاشة إنشاء أدمن.

تنبيه مهم
----------
لا تنشر النسخة قبل إضافة DATABASE_URL و INITIAL_SETUP_KEY. عند عدم وجودهما سيوقف البرنامج تهيئة المستخدمين
ويعرض رسالة واضحة بدل إنشاء مستخدمين محليين غير متزامنين.
