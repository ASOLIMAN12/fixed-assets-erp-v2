Assets Pro v3.8.0 — حماية البيانات المركزية
============================================

مهم:
- لا توجد حماية مطلقة 100%، لكن هذه النسخة تضيف طبقات قوية داخل التطبيق وقاعدة البيانات.
- PostgreSQL هي قاعدة التشغيل الأساسية. Google Drive أو مجلد الشبكة يُستخدمان للنسخ الاحتياطي فقط، وليس لتشغيل قاعدة البيانات مباشرة.
- لا ترفع ملف .env أو أي مفتاح سري إلى GitHub.

ما تم تنفيذه في هذه النسخة
--------------------------
1) تخزين مركزي في PostgreSQL للمستخدمين والأصول والجرد والقيود وبيانات HR.
2) معاملات Database Transactions حتى لا يُحفظ نصف التعديل عند حدوث خطأ.
3) رقم إصدار لكل مستند مركزي ومنع تعارض تعديل جهازين في الوقت نفسه.
4) بصمة SHA-256 لكل نسخة واكتشاف تلف أو تغيير غير صحيح في البيانات.
5) الاحتفاظ بآخر 50 إصدارًا لكل نوع بيانات، مع إمكانية الاستعادة بواسطة المدير.
6) سجل تدقيق مركزي لتعديلات البيانات وسجل أمني للدخول والفشل وتغيير المستخدمين وكلمات المرور.
7) إيقاف محاولات تسجيل الدخول لمدة 15 دقيقة بعد 5 محاولات خاطئة خلال 15 دقيقة.
8) كلمات مرور جديدة بطول 12 حرفًا على الأقل، وتخزينها باستخدام scrypt مع salt عشوائي.
9) جلسات دخول داخل Cookie محمي HttpOnly وSecure وSameSite، وتنتهي بعد 12 ساعة.
10) صلاحيات على واجهات الخادم؛ إخفاء الشاشة وحده ليس وسيلة الحماية.
11) ترويسات حماية للمتصفح: CSP وHSTS ومنع iframe ومنع MIME sniffing وسياسة Referrer صارمة.
12) Rate limit عام، وفحص Origin، ومنع مفاتيح JSON الخطرة والطلبات ذات التركيب المفرط.
13) منع تنزيل ملفات المصدر وقواعد JSON وملفات الأسرار من رابط الموقع.
14) رسائل أخطاء عامة للمستخدم مع Request ID للتتبع دون كشف تفاصيل الخادم.

متغيرات التشغيل المطلوبة
------------------------
NODE_ENV=production
DATABASE_URL=Internal Database URL من PostgreSQL عندما يكون التطبيق والقاعدة على Render نفسه
INITIAL_SETUP_KEY=قيمة عشوائية 32 حرفًا أو أكثر (مطلوبة للتهيئة الأولى فقط)
RESEND_API_KEY=مفتاح Resend السري
RECOVERY_FROM_EMAIL=عنوان إرسال موثق في Resend

متغيرات اختيارية موصى بها
-------------------------
PASSWORD_MIN_LENGTH=12
ALLOWED_ORIGINS=https://اسم-النطاق-الفعلي
DATABASE_SSL=false عند استخدام Render Internal Database URL أو شبكة داخلية موثوقة

تثبيت Render
------------
1) ارفع ملفات v3.8.0 إلى GitHub، مع التأكد أن .env غير موجود في الرفع.
2) اترك DATABASE_URL الحالي كما هو حتى لا تفقد ارتباط قاعدة البيانات الحالية.
3) من Render نفّذ Clear build cache & deploy.
4) تأكد من ظهور السطرين:
   Assets Pro central authentication database is ready
   Assets Pro protected central data store is ready
5) افتح /api/health وتأكد أن centralAuth وcentralData كلاهما true.

تثبيت السيرفر الداخلي للشركة
----------------------------
- يفضل VM أو جهاز مستقل للتطبيق؛ لا تثبته داخل برنامج Iscon نفسه.
- شغّل Node.js وPostgreSQL كخدمتين بحسابي خدمة محدودي الصلاحية.
- ضع HTTPS أمام Node باستخدام IIS Reverse Proxy أو Nginx، ولا تفتح منفذ Node مباشرة للإنترنت.
- امنع منفذ PostgreSQL 5432 من الإنترنت. اسمح به فقط من خادم التطبيق.
- الوصول من خارج الشركة يكون عبر VPN مع MFA، وليس Port Forwarding مباشر.
- فعّل تحديثات Windows/OS، الجدار الناري، EDR/مكافحة الفيروسات، وتشفير القرص BitLocker.
- ضع ملفات النسخ الاحتياطي في جهاز/NAS منفصل بصلاحية كتابة لحساب النسخ فقط.
- عند الانتقال النهائي للسيرفر الداخلي لن تحتاج اشتراك PostgreSQL على Render، بشرط أن يعمل التطبيق والقاعدة داخليًا. رابط Render الخارجي لن يكون مطلوبًا إلا إذا قررت الاحتفاظ به.

النسخ الاحتياطي ومنع التلف
--------------------------
- يوجد scripts/backup-postgres.ps1 لإنشاء نسخة pg_dump مضغوطة وبصمة SHA-256 وحذف النسخ الأقدم من 30 يومًا.
- شغّل النسخ يوميًا عبر Windows Task Scheduler بحساب خدمة، واحتفظ بسياسة 3-2-1:
  3 نسخ، على وسيطين مختلفين، ونسخة واحدة خارج السيرفر/غير متصلة دائمًا.
- يمكن نسخ ملفات .dump الناتجة إلى Google Drive أو مجلد Network Share. لا تشارك مجلد قاعدة PostgreSQL الحي نفسه.
- اختبر الاستعادة شهريًا على قاعدة اختبار منفصلة. النسخة التي لم تُختبر ليست ضمانًا للاستعادة.
- لا تنفذ الاستعادة فوق قاعدة الإنتاج إلا بواسطة مسؤول IT وبعد أخذ نسخة جديدة.

تقوية إضافية خارج البرنامج (ضرورية لأقصى حماية)
------------------------------------------------
- MFA على GitHub وRender وResend وحساب مسؤول السيرفر.
- Branch protection ومراجعة التغييرات قبل الدمج إلى main.
- تدوير المفاتيح فور الاشتباه، وعدم إرسالها عبر WhatsApp أو البريد العادي.
- مراقبة سجل الأحداث والتنبيهات، ومراجعة محاولات الدخول الفاشلة دوريًا.
- فحص ثغرات وتحديث dependencies بشكل دوري بعد اختبار نسخة تجريبية.
- خطة طوارئ مكتوبة تحدد مسؤول الاستعادة وزمن الاستعادة المقبول.

ملاحظة عن الأجهزة
-----------------
- على Render: الرابط يفتح من أي جهاز متصل بالإنترنت بعد تسجيل الدخول الصحيح.
- على السيرفر الداخلي: يفتح داخل شبكة الشركة، ومن الخارج فقط عن طريق VPN إذا أعده مسؤول الشبكة.
